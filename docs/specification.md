# sharedimp — specification (Python side)

**The specification of `sharedimp` is a single document shared by the R and the
Python package:**

> `sharedimp-r/docs/specification.md` —
> <https://github.com/dsc-chiba-u/sharedimp-r/blob/main/docs/specification.md>
> ("common algorithm specification (R / Python)", v0.1, reconciled 2026-11-13)

That document is the single source of truth. This file does not restate it. It
records, for the Python package:

1. which revision of the common specification the package was checked against
   (§1) and a short orientation (§2);
2. how each section is realised in Python and where it is tested (§3);
3. Python-specific behaviour and every intentional deviation (§4) — the common
   specification requires deviations to be recorded in the deviating
   repository;
4. the status of the changes the common specification asked of this package
   (§5), what was verified across the two languages (§6), and the remaining
   differences and limits (§7).

Section numbers "spec §n" refer to the common specification.

## 2. Orientation (non-normative summary)

For every anchor feature and every train/assessment split: every other feature
is regressed on the anchor by OLS on the training rows and replaced by its
residual, with the same coefficients applied to the assessment rows; a Full
model (raw anchor in its original column position + residualized others) and a
Reduced model (the same without the anchor column) are fitted with identical
settings and scored on the assessment rows; `importance = score_full −
score_reduced`, where scores are oriented greater-is-better. The reported
importance is the unweighted mean over the splits in which it is defined.
Negative values are kept. There is no inference and no direction diagnostic.

### 4.2 Default metric (spec §9.1)

`scoring=None` selects the common default: mean squared error for regressors,
multinomial log loss for classifiers, both as greater-is-better scores, so a
call without `scoring` computes the same quantity as an R call without
`metric`. Details:

* The classifier default is `common_scorer("log_loss")`, reported under the
  name `neg_log_loss`. It gives the same value as scikit-learn's
  `"neg_log_loss"` scorer and stays defined when a class is missing from a
  training or assessment set (such a class has probability 0, clipped at
  `2⁻⁵²`), as the R implementation does.
* A classifier without `predict_proba` has no default metric: a `TypeError`
  asks for an explicit `scoring`.
* The estimator's own `score` method (R² / accuracy) is no longer used; request
  it with `scoring="r2"` / `scoring="accuracy"`.
* The sign never depends on the metric: `importance = score_full −
  score_reduced` with greater-is-better scores, so for both defaults a positive
  importance means a lower loss with the anchor.

### 4.3 Learner failures (spec §10)

A *failure* of one (split, feature) pair is any of:

* an exception raised while fitting, predicting or scoring the Full or the
  Reduced model;
* **non-finite predictions** on the assessment rows. Scorers receive the fitted
  model rather than its predictions, and some metrics turn a `NaN` prediction
  into a `NaN` score without raising, so the package inspects the predictions
  itself, once per fitted model: `predict_proba` (or, failing that,
  `decision_function`) for classifiers, `predict` otherwise. This costs one
  additional prediction pass on the assessment rows per model;
* a classifier's training set that contains a single class (raised by the
  package, also for learners that would accept it).

Handling:

* `on_error="warn"` (default): both scores and the importance of that pair are
  `NaN`, the message is stored in the `error` column as
  `"<ExceptionType>: <message>"`, the remaining pairs are evaluated, and one
  `UserWarning` reports the number of failures and the first message. Each
  feature is aggregated over its successful splits; `n_splits` is their number;
  with none, the summary values are `NaN` and `n_splits = 0`.
* `on_error="error"`: the original exception is re-raised immediately.
  Cross-language comparisons use this mode, so that a failure cannot be
  mistaken for a value.
* Not failures: errors in the inputs or in the residualization (raised before
  any learner runs), and a metric that is undefined on a split although the
  predictions are finite (e.g. `rsq` for a constant prediction): its `NaN` is
  excluded from the aggregation and from `n_splits`, with `error` empty — as
  in R.

The failing rows, the scores of the other rows, `n_splits` and the single
warning agree with R for a failing fit, for non-finite predictions and for a
single-class training set (§6). The error *messages* are each language's own.

### 4.4 Other language-specific points

| Topic | Python | R |
| --- | --- | --- |
| `split` label (spec §11.2) | 0-based | 1-based |
| Extra per-split columns | `error` (`None` or `"<ExceptionType>: <message>"`) | `id`, `id2`, `error` (`NA` or the condition message) |
| Names for unnamed input | `x0, x1, …` | `V1, V2, …` |
| Class level order | sorted labels (`estimator.classes_`) | factor levels |
| Overlapping training/assessment rows | accepted (used for in-sample closed-form tests) | rejected |
| Fit-time weights | `fit_params={"sample_weight": …}` (also applied to the null model); metrics are unweighted | not available |
| `accuracy` | scikit-learn's `"accuracy"` scorer uses `predict`; the spec's "argmax of the probabilities" is `common_scorer("accuracy")`. They coincide when `predict` is that argmax (not for `SVC(probability=True)`) | argmax labels |
| Rank-deficient designs with OLS | the estimator is used as given. `LinearRegression`, NumPy and SciPy least-squares routines each disagree with R on some rank-deficient design or stack ([`rank_deficiency.md`](rank_deficiency.md)); the parity tests use the test-only `AliasingOLS` there | `lm.fit`: pivoted QR, tolerance `1e-7`, aliased coefficients set to 0 |

These are differences by design, allowed or recorded by the common
specification; none is a defect. For a cross-language comparison, pass
explicit splits and a deterministic learner, and use `on_error="error"`.

## 6. Cross-language verification

`tests/test_cross_language.py` compares the Python package with numbers
produced by **running R**: `tests/fixtures/cross_language/r_reference.json`,
generated by `generate_r_reference.R` from `sharedimp-r` at commit `92f9ecb`
(R 4.4.3, `yardstick` 1.4.0, `nnet` 7.3.21) on the shared inputs
`inputs.json`. The R output is compared directly: same column names, same
column order of the representations, same row order of the per-split table,
same orientation of the scores. The only adaptation is the `split` label
(R 1-based, Python 0-based, spec §11.2).

| # | Compared | Designs | Tolerance | Observed |
| --- | --- | --- | --- | --- |
| 1 | Residualization slopes and intercepts; D1 and D3 flags | regular; duplicate + affine copy (D3); column constant on the training rows (D1, D2) | `1e-8` | agree |
| 2 | Full and Reduced training and assessment matrices, column names and order | same | `1e-8` | agree |
| 3 | Predictions of the Full and the Reduced OLS model; null-model predictions (`p = 1`) | same | `1e-8` | agree |
| 4 | Per-split table: `feature`, `split`, `n_train`, `n_test`, `score_full`, `score_reduced`, `importance`, failed rows | every case below | per learner | agree |
| 5 | Summary table: `importance`, `importance_std`, `score_full`, `score_reduced`, `n_splits` | every case below | per learner | agree |
| 6 | Default metric (neither side names a metric) | regression, binary, multiclass, `p = 1`, spec §15.1 fixture | per learner | agree; both resolve to `mse` / `log_loss` |
| 7 | Exact collinearity end to end | duplicate + affine copy; spec §15.1 with `x1_dup` | `1e-8` | agree; a collinear copy gets the importance of its original |
| 8 | `p = 1` | regression (`mse`, `r2`), binary (`log_loss`, `accuracy`) | per learner | agree |
| 9 | Learner failures with `on_error="warn"`: failing fit, non-finite predictions, single-class training set; and that `on_error="error"` aborts | regular design | `1e-8` | same failed rows, same scores elsewhere, same `n_splits`, one warning on both sides |
| — | Common metric values vs. `yardstick` on fixed predictions | — | `1e-12` | agree |

Learners and their tolerances (observed maximum over all columns of both tables):

| Learner (R / Python) | Metrics compared | Tolerance | Observed |
| --- | --- | --- | --- |
| `lm.fit` / `LinearRegression` (full-rank designs) | `mse`, `rmse`, `mae`, `r2`, `rsq`, default | `1e-8` | ≤ 6.8e-14 |
| `lm.fit` / test-only `AliasingOLS` (rank-deficient designs) | `mse`, default | `1e-8` | ≤ 7.1e-14 |
| `lm.fit` vs. null model, `p = 1` / `LinearRegression` vs. `DummyRegressor` | `mse`, `r2`, default | `1e-8` | ≤ 4.7e-15 |
| `glm.fit` / `LogisticRegression(C=inf, solver="newton-cholesky", tol=1e-12)` | `log_loss`, default | `1e-8` | 2.5e-9 |
| same | `accuracy`, `roc_auc` | `1e-8` | ≤ 5.6e-16 |
| `nnet::multinom` / `LogisticRegression(C=inf, tol=1e-12)` (L-BFGS) | `log_loss` (default) | **`1e-4`** | 2.9e-5 (scikit-learn 1.9.1), 4.0e-5 (1.3.2) |
| same | `accuracy`, `roc_auc` | `1e-8` | ≤ 5.6e-16 |

The tests pass with these tolerances on both dependency stacks (scikit-learn
1.9.1 / NumPy 2.4.6 and scikit-learn 1.3.2 / NumPy 1.23.5).

**Exception to `1e-8`.** The multinomial log loss agrees only to about `3e-5`:
`nnet::multinom` stops its BFGS iterations at a looser optimum than a
converged maximum-likelihood fit. That is the accuracy of the R learner, not
of the importance computation; with the same fitted probabilities the metric
itself agrees to `1e-12`.

**Not verified.**

* Stochastic learners (random forests, boosting): the two languages use
  different implementations and random number generators; no numerical
  identity is expected or tested.
* Randomly generated folds: the comparison always uses explicit fold labels.
* Other common metrics for the classification learners than those listed
  (`roc_auc` and `accuracy` are compared; e.g. `r2`-type metrics do not apply).
* Fit-time weights (Python only) and R's `id`/`id2` columns (R only).
* The exact text of error messages.
* Other platforms than Linux x86-64.

## 7. Status: differences, limits, open problems

**Open problems in the implementation: none.** Every item of the common
specification is implemented and tested (§3), every change requested of this
package is done (§5), and every item raised with the R side is resolved
([`r_side_changes.md`](r_side_changes.md)).

**Open items in the common specification: none.**

**Language-specific differences (by design; not defects).** All are listed in
§4.4 and acknowledged in the common specification:

| Difference | Where specified |
| --- | --- |
| `split` label: 0-based in Python, 1-based in R | spec §11.2 |
| Extra per-split columns: `error` in Python; `id`, `id2`, `error` in R | spec §11.2 |
| Text of error messages | spec §10 |
| Default names for unnamed input (`x0…` / `V1…`) | spec §3 |
| Learner: required argument in Python; default random forest in R | spec §8 |
| Fit-time weights: Python only | spec §16 (recorded deviation) |
| Overlapping training/assessment rows: accepted in Python, rejected in R | spec §16 (recorded deviation) |
| Randomly generated folds differ (different generators) | spec §4, §14 |

**Limits of numerical agreement (properties of learners, not of the
importance definition).**

| Limit | Record |
| --- | --- |
| Stochastic learners (forests, boosting) cannot be compared numerically across languages | spec §8.2, §14 |
| Iteratively fitted models agree as far as their optimisers converge: multinomial logistic regression to about `3e-5` | §6 |
| On rank-deficient designs ordinary least squares is not unique; `LinearRegression`, NumPy and SciPy routines can differ from R's `lm.fit` | spec §8.1, §15.4; [`rank_deficiency.md`](rank_deficiency.md) |

**Not verified** (see also §6): platforms other than Linux x86-64 for the
comparison with R; the classification path of the official UMFI
implementations (`relation_to_umfi.md`).
